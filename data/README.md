# 数据目录说明

## 数据管理策略（方案C）
根据老大要求，采用"只提交数据结构和示例数据"的策略。

## 目录结构
```
data/
├── structure/          # 数据结构定义（提交到GitHub）
│   ├── financial/     # 财报数据结构
│   ├── stock/         # 股票数据结构  
│   └── trading/       # 交易数据结构
├── sample/            # 示例数据（提交到GitHub）
│   ├── financial_sample.csv
│   ├── stock_sample.csv
│   └── trading_sample.csv
├── real/              # 真实数据（不提交，.gitignore排除）
│   ├── financial/     # 真实财报数据
│   ├── stock/         # 真实股票数据
│   └── trading/       # 真实交易数据
└── cache/             # 缓存数据（不提交，.gitignore排除）
```

## 数据结构文件
所有数据结构文件都放在 `structure/` 目录中，包括：
1. 数据库表结构定义
2. 数据字段说明
3. 数据验证规则
4. 数据关系图

## 示例数据
`sample/` 目录包含：
1. 小规模示例数据集
2. 用于测试和演示
3. 不包含真实敏感数据

## 真实数据管理
真实数据存储在 `real/` 目录，通过以下方式管理：
1. **本地备份**：定期备份到外部存储
2. **云端同步**：使用云存储服务（如iCloud、Google Drive）
3. **版本控制**：重要数据变更记录在 `data/CHANGELOG.md`

## 数据更新流程
1. 从数据源获取最新数据 → 保存到 `real/` 目录
2. 更新数据结构（如有变化）→ 更新 `structure/` 目录
3. 生成新的示例数据 → 更新 `sample/` 目录
4. 提交结构变更到GitHub

## 注意事项
1. 不要将真实数据提交到GitHub
2. 定期备份真实数据
3. 数据变更时更新文档
4. 保持示例数据与真实数据结构一致
